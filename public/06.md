# 6 名前に何があるのか（What's in a name?）

[目次へ戻る](../README.md) ／ [原文（英語）](https://protege.stanford.edu/publications/ontology_development/ontology101-noy-mcguinness.html)

オントロジーの概念について命名規則（naming convention）を定め、その規則を厳密に守ることは、オントロジーを理解しやすくするだけでなく、よくあるモデリングの誤りのいくつかを避ける助けにもなる。概念の名前の付け方には、多くの選択肢がある。どれか一つを選ぶ特別な理由がないことも多い。しかし、次のことが必要である。

> *クラスとスロットの命名規則を定め、それを守る。*

知識表現システムの次のような特徴が、命名規則の選び方に影響する。

- そのシステムでは、クラス、スロット、インスタンスが同じ名前空間（name space）にあるか。つまり、同じ名前のクラスとスロット（たとえばクラス `winery` とスロット `winery`）を持つことが許されるか。

- そのシステムは大文字と小文字を区別する（case-sensitive）か。つまり、大文字と小文字の違いだけの名前（たとえば `Winery` と `winery`）を、異なる名前として扱うか。

- そのシステムでは、名前にどんな区切り文字（delimiter）が許されるか。つまり、名前に空白、コンマ、アスタリスクなどを含めることができるか。

たとえば Protégé-2000 は、すべてのフレーム（frame）について一つの名前空間を持つ。また、大文字と小文字を区別する。したがって、クラス `winery` とスロット `winery` を持つことはできない。しかし、クラス `Winery`（大文字であることに注意）とスロット `winery` を持つことはできる。一方、CLASSIC は大文字と小文字を区別せず、クラス、スロット、個体に別々の名前空間を持つ。したがって、システムの観点からは、クラスとスロットの両方に `Winery` という名前を付けても問題はない。

## 6.1 大文字の使い方と区切り文字

まず、概念の名前で大文字の使い方をそろえると、オントロジーの読みやすさを大きく高められる。たとえば、クラス名は大文字で始め、スロット名には小文字を使うのが一般的である（システムが大文字と小文字を区別する場合）。

概念の名前が複数の単語を含む場合（たとえば `Meal course`）、単語を区切る必要がある。考えられる選択肢をいくつか挙げる。

- 空白を使う：`Meal course`（Protégé を含む多くのシステムでは、概念の名前に空白を使える）。

- 単語をつなげて、各単語の先頭を大文字にする：`MealCourse`

- 名前の中で、アンダースコア、ダッシュ、その他の区切り文字を使う：`Meal_Course`、`Meal_course`、`Meal-Course`、`Meal-course`。（区切り文字を使う場合は、各単語の先頭を大文字にするかどうかも決める必要がある）

知識表現システムが名前に空白を許すなら、空白を使うのが、多くのオントロジー開発者にとって最も直感的な解決策かもしれない。しかし、自分のシステムがやりとりするかもしれないほかのシステムのことも考えておくことが重要である。それらのシステムが空白を使わない場合や、表示に使う媒体が空白をうまく扱えない場合には、別の方法を使うのが有益なことがある。

## 6.2 単数形か複数形か

クラス名は、物の集まりを表す。たとえば、クラス `Wine` は実際にはすべてのワインを表す。したがって、設計者によっては、このクラスを `Wine` ではなく `Wines` と呼ぶほうが自然かもしれない。どちらの選択肢も、もう一方より優れているわけでも劣っているわけでもない（実際には、クラス名に単数形を使うことのほうが多いが）。しかし、どちらを選んだとしても、オントロジー全体を通じて一貫させるべきである。システムによっては、概念の名前に単数形と複数形のどちらを使うかを利用者があらかじめ宣言することを求め、その選択から外れることを許さないものさえある。

常に同じ形を使うことで、設計者が、クラス `Wines` を作り、次にそのサブクラスとしてクラス `Wine` を作る、といったモデリングの誤りを犯すことも防げる（4.1 節を参照）。

## 6.3 接頭辞と接尾辞の規則

知識ベースの方法論の中には、クラスとスロットを区別するために、名前に接頭辞（prefix）や接尾辞（suffix）の規則を使うことを勧めるものがある。よくある二つのやり方は、スロット名に接頭辞 `has-` を付けるか、接尾辞 `–of` を付けるかである。`has-` の規則を選べば、私たちのスロットは `has-maker` や `has-winery` になる。`of-` の規則を選べば、スロットは `maker-of` や `winery-of` になる。このやり方では、用語を見た人は誰でも、その用語がクラスかスロットかをすぐに判断できる。ただし、用語の名前は少し長くなる。

【訳注】原文は、接尾辞を「`–of`」と書いたすぐあとで、同じ規則を「`of-` の規則」と呼んでいる。例（`maker-of`、`winery-of`）から分かるとおり、どちらも名前の末尾に `-of` を付ける規則を指す。訳文は原文の表記のままにした。

## 6.4 名前の付け方についてのその他の考慮事項

命名規則を定めるときに考えておくべきことを、さらにいくつか挙げる。

- 概念の名前に「class」「property」「slot」などの文字列を付け加えない。

たとえば、概念がクラスなのかスロットなのかは、文脈から常に明らかである。さらに、クラスとスロットに異なる命名規則（たとえば、それぞれ大文字で始める、大文字で始めない）を使っていれば、名前そのものが、その概念が何であるかを示すことになる。

- 概念の名前では、ふつう略語を避けるのがよい（つまり、`Cab` ではなく `Cabernet Sauvignon` を使う）。

- あるクラスの直接のサブクラスの名前は、すべてスーパークラスの名前を含むか、すべて含まないかのどちらかにすべきである。たとえば、赤ワインと白ワインを表すために `Wine` クラスのサブクラスを二つ作るなら、二つのサブクラスの名前は、`Red Wine` と `White Wine` か、`Red` と `White` のどちらかにすべきであり、`Red Wine` と `White` にすべきではない。
